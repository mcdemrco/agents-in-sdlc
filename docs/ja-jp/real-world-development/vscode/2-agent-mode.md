単純な更新でも、複数のファイルを変更し、テストなどを実行する必要があります。開発者は通常、必要なファイルを見つけ、変更を加え、テストを実行し、エラーを修正し、見落としたファイルに追加の変更を行います。こうした作業が繰り返されることもあります。

このようなときに役立つのが Copilot エージェントモードです。

エージェントモードは、IDE 内でより自律的に作業できるように設計されています。開発者と同じようにプロジェクト構成を調べ、必要な変更を行い、テストなどのタスクを実行し、見つかった問題を自動的に修正します。エージェントモードを使って Web サイトに機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる用途の機能です。エージェントモードは IDE 内で動作するため、すばやく結果を確認して対話できます。cloud agent はチームの一員のように非同期で動作し、issue とプルリクエストを通じてやり取りします。

この演習では、次の操作を行います。

- Copilot エージェントモードにプロジェクトを調べさせ、関連するファイルを見つけて、複数ファイルにわたる変更を行います。
- GitHub Copilot エージェントモードでユーザー インターフェイス (UI) とデータ層にまたがる機能を実装します。
- 生成された変更とテストをレビューしてから、コードベースにマージします。

## シナリオ

ゲームの一覧が増えてきたため、カテゴリとパブリッシャーで絞り込めるようにします。前の演習で追加した publishers ヘルパーを活用し、Copilot エージェントモードで残りのデータ層、UI、テストの作業を行います。

## Tailspin Toys Web サイトを実行する

変更を加える前に、Tailspin Toys Web サイトの現在の機能を確認します。

この Web サイトは、開発者をテーマにしたボードゲームのクラウドファンディング プラットフォームです。ゲームの一覧と詳細を表示します。サイトは Astro の単一アプリで、ビルド時にページを静的 HTML として生成します。ページは frontmatter 内で Drizzle ORM を使ってローカルの SQLite データベースを直接クエリします。独立したバックエンドのアプリケーション プログラミング インターフェイス (API) やクライアント側のユーザー インターフェイス (UI) フレームワークはありません。再利用可能なデータアクセス ヘルパーは `src/lib/` に置き、操作性は標準のドキュメント オブジェクト モデル (DOM) API を使った小規模な Astro `<script>` で追加します。

### Web サイトを起動する

`npm run dev` タスクを使うと、Astro の単一の開発サーバーを起動できます。GitHub Codespace で次の手順を実行します。

1. 前の演習で使った Codespace に戻ります。`main` ブランチにいることを確認します。
2. Codespace 内で <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して新しいターミナルを開きます。
3. `main` を更新し、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro の開発サーバーが起動すると、次のような URL を示すメッセージが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くダイアログが表示された場合は、**x** を選択して閉じます。

5. ターミナルで <kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら、Astro サーバーのアドレス `http://localhost:4321` を選択して Web サイトを開きます。

> [!NOTE]
> Codespace のターミナルで localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` に転送されます。これは、Web サーバーをホストしている codespace へのプライベート トンネルです。

### Web サイトを確認する

Web サイトを起動したら、現在の機能を確認します。主な機能は次のとおりです。

- **Home Page**: ボードゲームの一覧、タイトル、画像、説明を表示します。
- **Game Details Page**: ゲームを選択すると、タイトル、説明、パブリッシャー、カテゴリなどの詳細を表示します。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に、codespace に戻り、Copilot Chat パネルを開いて **New Chat** を選択し、新しい会話を始めます。モードとモデルの選択は演習によって異なります。必要な手順は各演習で説明します。

Web サイトは動作していますが、新しい機能を追加します。まずバックログを確認しましょう。テンプレートからプロジェクトを作成すると、issue のバックログも自動的に作成されています。GitHub Copilot に内容を表示させます。

1. Chat ビューのエージェント選択メニューで **Agent** を選択します。エージェントモードは、自律的に計画して複数のファイルを変更し、ターミナル コマンドやツールを実行します。

   ![Chat ビューのエージェント選択メニューを示すスクリーンショット。](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップは、特定のモデルを推奨するものではありません。作成時には Claude Sonnet 4.5 を使用したため、手順に含めています。比較的一貫した体験を提供することが目的ですが、大規模言語モデル (LLM) は確率的に動作するため、提案内容が異なる場合があります。これは通常の動作です。

> [!NOTE]
> Copilot が別の Model Context Protocol (MCP) コマンドを使う場合がありますが、タスクを完了できるはずです。

3. Copilot に次のプロンプトを送り、issue のバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。ユーザーに最も役立つ項目を基に優先順位を付けてください。
   ```

4. **Continue** を選択して、すべての issue を一覧表示するコマンドを実行します。
5. 生成された issue の一覧を確認します。

Copilot はユーザーに役立つと思われる順に項目を整理します。

## 指示ファイルを確認する

エージェントにコードを生成させる前に、作業のコンテキストを Copilot に伝える指示ファイルを確認します。Web サイトの機能追加に関するガイダンスを含む [ユーザー インターフェイス (UI) 指示ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使います。

1. Codespace で `.github/instructions/ui.instructions.md` を開きます。
2. 機能追加に関する全体的なガイダンスを確認します。次の内容が含まれます。
   - アーキテクチャの概要
   - コンポーネントの設計、テスト容易性、アクセシビリティの原則
   - Astro、Tailwind CSS、Drizzle など、ファイルの種類ごとの指示ファイルへのリンク

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルの場所からの相対パスです。指示を再利用し、大きな指示を小さく分け、Copilot に例やテンプレートを示せます。

## フィルタリング機能を実装する

フィルタリングを完成させるには、少なくとも 3 つの変更が必要です。

- データ層 (`src/lib/`) のフィルタリング ロジックを追加または調整します。
- フィルタリングの動作に関するテストを追加または更新します。
- ゲーム一覧ページにフィルタリング UI を追加します。

コードベースにマージする前にテストを実行し、成功することも必要です。Copilot エージェントモードにこれらの作業を依頼しましょう。

1. 今の会話を続けるか、**New Chat** を選択して新しい会話を始めます。
2. **Add Context**、**Instructions**、**ui** の順に選び、指示ファイルを追加します。

   ![UI 指示ファイルを選択する例を示すスクリーンショット](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント選択メニューで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニューを示すスクリーンショット。](../../../_images/shared-chat-mode-selector.png)

4. モデルが **Claude Sonnet 4.5** のままであることを確認します。
5. バックログの関連 issue に基づいて機能を実装するよう、次のプロンプトを送ります。

   ```plaintext
   バックログにある関連する GitHub issue の要件に基づいて、サイトにパブリッシャーとカテゴリによるフィルタリングを追加してください。前の演習で publishers ヘルパーを作成済みです。必要に応じてその作業を維持して改善し、残りのデータ層、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調べ、機能に関連するファイルを見つける様子を確認します。データ層のヘルパー、UI、テストを見つけた後、ファイルを変更してテストを実行します。

   ![Copilot がプロジェクトのファイルを調べる様子を示すスクリーンショット](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行などを行うため、完了まで数分かかることがあります。作業中、コード エディターに **Keep** と **Undo** が表示される場合があります。Copilot が完了すると、すべての変更に **Keep** または **Undo** が表示されるため、作業中に選択する必要はありません。

7. Copilot に求められたら **Continue** を選択してテストを実行します。

   ![Copilot Chat でテストの実行を確認するダイアログを示すスクリーンショット](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に一時停止したり、テストが失敗したりすることがあります。Copilot はコード生成とテストを繰り返し、エラーがないと判断するまで作業を続けます。

   ![Copilot エージェントモードの完了したチャット セッションを示すスクリーンショット](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを開いているブラウザーに戻り、新機能を試します。
11. 動作を確認してコードをレビューしたら、Copilot Chat ウィンドウで **Keep** を選択します。

## まとめと次のステップ

GitHub Copilot エージェントモードを使って Tailspin Toys Web サイトに機能を追加しました。この演習では、次のことを確認しました。

- Copilot エージェントモードにプロジェクトを調べさせ、関連ファイルを見つけて、複数ファイルにわたる変更を行いました。
- GitHub Copilot エージェントモードでユーザー インターフェイスとデータ層にまたがる機能を実装しました。
- コードベースにマージする前に、Copilot が生成した変更とテストをレビューしました。

### 発展演習 - ページネーションを実装する

ゲーム一覧が増えると、ページネーションが必要になります。この演習で学んだ方法を使い、Copilot にページネーションを追加させます。次の点を検討してください。

- 既存の指示ファイルなど、プロジェクトのベストプラクティスに従います。
- ページサイズをユーザーが選べるようにするか、固定にするかなど、実装方法を考えます。
- 希望する実装に必要なガイダンスを、プロンプトで Copilot に伝えます。
- Copilot に変更やコンテキストを求めながら、何度かやり取りすることがあります。これは Copilot を使う通常の流れです。
