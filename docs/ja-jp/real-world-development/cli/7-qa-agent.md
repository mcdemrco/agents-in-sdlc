これまでに `quality-checks` スキルで自動チェックを実行し、Playwright の Model Context Protocol (MCP) サーバーでブラウザー上のフィルタリング操作を確認しました。次は、それらの機能を明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次の操作を行います。

- カスタムエージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証 (QA) プロファイルを作成して調べます。
- QA エージェントを選択し、フィルタリングの issue に照らした報告を確認します。

## シナリオ

Tailspin Toys は、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザーでの動作を一貫してレビューしたいと考えています。カスタムエージェントを使うと、この QA プロセスを調整し、再利用できる報告を作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的な役割です。プロファイルにはエージェントの目的、指示、使用可能なツールを記述します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまで使用したカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を記述し、`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、要件の評価と結果の報告に、これらの機能をどう使うかを Copilot に伝えます。ほかの機能を置き換えるものではなく、新しい会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを Copilot に作成させます。プロファイルには、QA で実行するチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. デフォルト エージェントに次のプロンプトを送り、新しいカスタムエージェントを作成します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を issue と合意した要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、テスト範囲が不足している場合はテストを追加してください。

   各要件について、根拠を示して pass、fail、blocked のいずれかで報告してください。実装コードを変更する前に確認を求め、変更をコミットしたり、プルリクエストを開いたりしてはいけません。

   まずプロファイルを作成するだけにして、私がレビューできるようにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA の手順と制約がプロファイルに反映されているか確認します。確認だけが目的なのに、プロファイルが不完全だったり範囲が広すぎたりして機能を変更する事態を防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は省略できますが、含めるとエージェントの表示名が明確になります。
3. 指示を読み、QA が要件から始め、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. 根拠を示して報告すること、実装コードの変更前に確認を求めること、コミットやプルリクエストの作成をしないことを確認します。
5. これらの役割や制約が抜けている場合は、続行する前にデフォルト エージェントにプロファイルを修正させます。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイル作成後に同じフィルタリングの会話を再開し、QA を選択すると、既に共有されている issue と計画を利用できます。

1. 次のプロンプトを入力してエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> エージェントを作成した直後は、利用可能なエージェント一覧に表示されない場合があります。上記のコマンドで有効にできます。

2. 次のプロンプトを送り、QA エージェントに機能をレビューさせます。

   ```plaintext
   issue と計画で決めた内容に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか。
   ```

3. QA エージェントが作業を始めることを確認します。
4. 作業が終わったら、報告内容を読みます。

## まとめと次のステップ

再利用可能な専門的役割をワークフローに追加し、その作業をレビューしました。このレッスンでは、次の操作を行いました。

- カスタムエージェントが指示、スキル、MCP ツールと連携する方法を確認しました。
- 再利用可能な品質保証プロファイルを作成して調べました。
- QA エージェントを選択し、フィルタリングの issue に照らした報告を確認しました。
