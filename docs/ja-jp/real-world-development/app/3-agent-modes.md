プロジェクトに小さな機能を追加しましたが、大きな変更には、より確実なプロセスが必要です。GitHub Copilot app は組織の既存のフローに沿って作業できるように設計されており、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。issue から新機能を実装し、コードが有効で機能が期待どおりに動作することを確認して、最終的にプロジェクトへマージします。

> [!NOTE]
> 機能のワークフローでは、同じセッションを使い続けます。通常は作業するファイルの種類ごとに異なるセッションやプルリクエスト (PR) を使いますが、ここでは主な概念に集中するため手順を簡略化します。

このレッスンでは、次の操作を行います。

- GitHub issue から新しいエージェント セッションを開始します。
- **Plan** モードで要件を定義します。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザーキャンバスで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、Model Context Protocol (MCP) による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、訪問者はカテゴリとパブリッシャーでゲームを絞り込む必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、実装前に合意が必要な詳細もあります。Plan モードで決定事項を整理してから、範囲を定めた実装を Autopilot に許可します。

## 背景

人工知能 (AI) コーディング エージェントを開発フローに加えても、基本は変わりません。むしろ、基本はより重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細を記述した登録済みの issue から始めます。
2. 実装する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードがレビューされ、継続的インテグレーションの処理が成功したら、コードをマージします。

> [!NOTE]
> 実際の手順はチームや組織によって異なりますが、多くの場合は上記の流れを基にしています。

この標準的な手順に沿うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビュー工程を通るようにします。

## セッションモード

**セッションモード**は、エージェントにどの程度の自律性を与えるかを制御します。プロンプト フィールドの下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: 開発者とエージェントが協力して作業します。エージェントは変更を提案し、次に進む前に開発者の入力を待ちます。
- **Plan**: エージェントが先に計画を作成します。エージェントが計画を実行する前に、開発者がレビューして承認します。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、入力を待たずに作業を反復します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue からセッションを開始する

開始前に、星評価の PR がマージ済みで、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリ フォルダーを選択し、リポジトリの上部ナビゲーションにある **Issues** を選択します。**Allow users to filter games by category and publisher** を開きます。これはテンプレートに含まれる既存の issue なので、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

   ![GitHub Copilot app の issue ビューで New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モード選択メニューで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行させます。自分のターミナルでは動作するのにセッションでは動作しない場合は、アプリの PATH またはバージョン管理ツールの設定を確認し、アプリを完全に終了して再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで npm を再インストールしないでください。

## フィルター機能を計画する

計画を立てると、Copilot がコードを書く前にアプローチを確認できます。issue から開始したため、Copilot は機能の要望をコンテキストとしてすでに把握しています。次のプロンプトを送信します。

```plaintext
この機能を実装してください。
```

Copilot の質問に回答し、計画を issue の受け入れ条件に照らし合わせます。カテゴリとパブリッシャーによる絞り込み、アクセシブルなコントロール、データアクセスの変更、テストが含まれることを確認します。複数のカテゴリの組み合わせや、該当するゲームがない場合の動作など、不明確な点を話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニットテスト、エンドツーエンド (E2E) テスト、型チェックを含めます。フィルタリング機能の実装とテストに範囲を絞り、品質ワークフローの完了後に PR を作成します。計画は承認前に修正を依頼し、後で検証できるよう issue の URL と合意した追加事項を手元に控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan**、または使用中のバージョンに表示される同様の選択肢を選択します。承認するとモードも切り替わると決めつけず、実際に有効なモードを確認してください。モード表示が **Autopilot** になっていることを確認します。

Copilot が実装を始めます。計画に沿ってコードを生成し、テストを実行しながら、作業を反復します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画をレビューしてください。依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決します。自分で起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同様にマージする前にレビューします。コードを確認し、サイトを実行して動作も確かめましょう。

1. **Changes** を開き、フィルタリングの実装とテストを確認します。
2. 複数カテゴリやパブリッシャーの組み合わせも含め、変更内容を issue と承認した追加事項に照らし合わせます。リポジトリの既存の指示に従っていることも確認します。
3. lint、ユニットテスト、E2E テスト、型チェックの結果を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、影響を受けるチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカル サーバーを再利用する場合があります。テスト対象が前のレッスンではなく、この worktree のサーバーであることを確認します。

## 新機能を試す

コードに問題がないように見えても、実際に動くか確認しましょう。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを Copilot に送り、アプリを起動してブラウザーキャンバスでページを開きます。

   ```plaintext
   アプリを起動して、ブラウザーキャンバスで開いてください。
   ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザー ウィンドウが開きます。
3. カテゴリを選択し、結果が一致することを確認します。フィルターを解除してからパブリッシャーを選択し、結果が一致することを確認します。
4. カテゴリとパブリッシャーを組み合わせ、issue と承認した計画に照らして結果を確認します。複数カテゴリに対応する場合は、合意した組み合わせの動作も検証します。
5. 該当するゲームがない組み合わせを試して、空の状態を確認します。フィルターを解除またはリセットし、一覧全体が戻ることを確認します。
6. 確認が終わったら、次のプロンプトを Copilot に送り、このセッションで起動した開発サーバーを停止します。

   ```plaintext
   開発サーバーを停止して、ブラウザーキャンバスを閉じてください。
   ```

## 次のレッスンでも同じセッションを使う

フィルタリングの PR はまだ作成またはマージしないでください。レッスン 4 から 8 まで、同じセッション、worktree、ブランチを使います。次はカスタム指示をフィルタリングのコードに適用し、スキルと QA の改善を追加してから、レッスン 8 でまとめた PR を作成してマージします。開発サーバーを停止した後は、セッションを終了せずに置いておき、次のレッスンで同じセッションに戻ります。

## まとめと次のステップ

- **Plan** モードで要件を定義しました。
- **Autopilot** モードで新機能を実装しました。
- コードをレビューしました。
- ブラウザーキャンバスで機能を手動で検証しました。
